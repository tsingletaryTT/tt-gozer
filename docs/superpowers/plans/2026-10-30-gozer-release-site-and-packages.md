# gozer release: explainer site and Debian packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the scoreboard page with a terminal-first explainer built from real gozer output and real history, and build a lintian-clean `tt-gozer` `.deb` in CI on every release tag.

**Architecture:** A build package `site_build/` (outside the `gozer` package, never shipped in the `.deb`) runs the real CLI against a fake box to produce terminal transcripts, derives the example afternoon and roster from a committed extract of the real history log, and fills one HTML template into `docs/index.html`. A `debian/` tree plus a minimal `pyproject.toml` builds an architecture-independent package with `pybuild`. Two GitHub Actions workflows run the tests, check the committed site is current, and on a tag build, lint, install-test and release the `.deb`.

**Tech Stack:** Python 3.10+ (stdlib only for the site build), pytest, debhelper-compat 13 with dh-python and pybuild, lintian, GitHub Actions, Docker or Podman for local package builds.

**Spec:** `docs/superpowers/specs/2026-10-30-gozer-release-site-and-packages-design.md`

## Global Constraints

- The command stays `gozer`. No binary, script or package is named `tt`.
- The package is `tt-gozer`, `Architecture: all`, source format `3.0 (native)`, `debhelper-compat (= 13)`, `Rules-Requires-Root: no`, `Depends: ${python3:Depends}`, `Recommends: tt-smi`.
- The package has no hand-written maintainer scripts (dh_python3's generated bytecode compile and clean scripts are allowed), enables nothing, and writes nothing to any home directory. The reconcile timer ships as a systemd user unit under `/usr/lib/systemd/user` and is never enabled.
- Skills install through `gozer-install-skills`, which links them into the calling user's `~/.claude/skills`.
- Python 3.10 or newer. CI pins one Python version for the site build. Install tests run on Debian 12, Ubuntu 22.04 and Ubuntu 24.04.
- The site is static: no JavaScript framework, no chart library, no custom fonts, no analytics, no server. It works at phone width and is readable without JavaScript.
- Palette: dark teal `#092221`, accent `#1B8EB1`, backgrounds `#F1F8F8` and `#C7D9D8`, semantic teal `#74C5DF`, green `#6FABA0`, yellow `#F6BC42`, red `#FF9E8A`.
- Every terminal example is real output from the real CLI. The example afternoon and roster come from the committed history extract. Task text never appears (reasons are dropped from the extract). Agent names appear as logged.
- "Who uses it" names only public repositories whose code or scripts call `gozer`, one line each, last section on the page. tt-rl is excluded.
- The site is a committed build in `docs/`; CI checks it is current and does not deploy it. The repository's Pages setting does not change.
- Plain-English copy: state findings directly, no "X, not Y" framings, no aphoristic closers (see the global CLAUDE.md). Sweep each new text file for `, not `, `rather than`, `instead of`, `reads as`, `honest`.
- Tag `v<version>` must equal `v` plus `gozer.__version__`. The version at the start of this plan is 0.3.9.

## Review Focus

- A history extract with no queue events, a single agent, or a lease with no matching release: the afternoon renders without a crash and the captions only state facts the data supports.
- An agent whose name is long or contains `:` or HTML characters: it is escaped on the page and does not break a lane block.
- A lease still open at the end of the window: its block runs to the window edge and is labelled as still running.
- `gozer-install-skills` run twice, run when `~/.claude/skills/<name>` is a real directory, and run with no `~/.claude` at all.
- The site build run on a machine whose own `~/.local/state/tt-gozer` and `/tmp/tt-gozer` hold real data: the output is unchanged and those directories are untouched.

### Task 6: The example afternoon

**Files:**
- Create: `site_build/afternoon.py`, `site/data/afternoon-2026-10-26.jsonl`, `scripts/make_afternoon_extract.py`
- Test: `tests/test_site_afternoon.py`

**Interfaces:**
- Produces:
  - `extract(events: list[dict], start: str, end: str) -> list[dict]` keeps `granted` and `queued` events inside the window, plus every `released` event whose `lease_id` was granted inside the window even if the release falls after it (so a long hold keeps its real duration). Each record has only these keys: `ts`, `event`, `who`, `chips`, `lease_id`, `ticket`, `duration_s`. It drops `reason`, `why`, `pid` and anything else.
  - `facts(records: list[dict]) -> dict` computes `{"rapid_cycles": {"who", "count", "typical_s"}, "longest_hold": {"who", "seconds"}, "waits": [{"who", "seconds"}], "fastest_handoff_s": int, "same_second_handoffs": int}` from the records only.
  - `captions(f: dict) -> list[str]` builds the caption sentences from `facts`, so a caption cannot state something the data does not show.
  - `lanes_html(records: list[dict], start: str, end: str) -> str` returns the timeline: one row per board, one block per lease, time left to right, agent names HTML-escaped, a lease that ends after the window drawn to the window edge and labelled "continues", and a lease with no release record labelled "still running".
- `scripts/make_afternoon_extract.py` reads `~/.local/state/tt-gozer/history.jsonl` and writes the extract for 2026-10-26T16:00:00Z to 2026-10-26T20:30:00Z. Run once; the output is committed.
